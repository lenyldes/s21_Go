Высоконадежный модульный веб-сервис для игры в «Крестики-нолики», спроектированный в соответствии с принципами чистой архитектуры (Clean Architecture / Onion Architecture) и инверсии управления (Inversion of Control, IoC). Управление жизненным циклом компонентов и внедрение зависимостей осуществляются посредством контейнера Uber Fx. Игровой процесс поддерживается искусственным интеллектом на базе алгоритма минимакс (Minimax), гарантирующего математически безошибочную стратегию игры. Проект реализован в многомодульной структуре Go с изолированными слоями Domain, Datasource, Web и DI.

---

## О проекте

Проект представляет собой реализацию классической пошаговой игры «Крестики-нолики» в виде распределенного клиент-серверного веб-приложения:
- **Бэкенд:** RESTful HTTP-сервис на Go, обеспечивающий создание игровых сессий, валидацию ходов, контроль целостности игрового состояния и расчет оптимальных ответных ходов ИИ.
- **Фронтенд:** Легковесный одностраничный веб-клиент (SPA) на чистом JavaScript (Fetch API) и HTML5/CSS3, взаимодействующий с API сервиса по протоколу HTTP и позволяющий гибко задавать целевой хост сервера.

Ключевой фокус проекта направлен на демонстрацию эталонного разделения зон ответственности (Separation of Concerns), абсолютную независимость ядра бизнес-логики от внешних фреймворков и баз данных, а также промышленное применение Dependency Injection (DI) в экосистеме Go.

## Ключевые навыки и освоенные концепции

- **Чистая архитектура (Clean Architecture / Onion Architecture):** Строгое разделение системы на независимые концентрические слои. Поток управления направлен снаружи внутрь к доменному ядру, при этом ядро не имеет зависимостей от деталей реализации инфраструктуры, веб-транспорта или хранилищ.
- **Инверсия управления (IoC) и принцип инверсии зависимостей (DIP):** Доменный слой определяет интерфейсы репозитория (`GameRepository`) и сервиса (`GameService`). Инфраструктурные слои реализуют данные интерфейсы, избавляя домен от жестких связей.
- **Контейнер внедрения зависимостей Uber Fx и Uber Dig:** Построение декларативного графа зависимостей приложения без написания шаблонного кода инициализации. Регистрация конструкторов через `fx.Provide`, управление жизненным циклом сервиса и запуск через `fx.Invoke`.
- **Структурированное логирование Zap:** Использование высокопроизводительного логирования `go.uber.org/zap`, интегрированного с диагностическими событиями Fx-контейнера.
- **Строгая изоляция моделей (Domain / DTO / Storage Entity):** Предотвращение протекания абстракций путем разделения моделей по слоям:
  - Доменные модели (`domain.Game`, `domain.Board`) оперируют матрицей 3х3 и семантическими сущностями игры.
  - Транспортные DTO (`GameRequest`, `GameResponse`, `BoardWeb`) инкапсулируют форматирование JSON и метаданные API.
  - Персистентные сущности (`GameEntity`, `BoardEntity`) оптимизированы под хранение (одномерный срез длины 9).
  - Специализированные мапперы реализуют бесконфликтную трансляцию данных на границах слоев.
- **Конкурентное in-memory хранилище:** Применение потокобезопасной структуры `sync.Map` для параллельной обработки запросов игровых сессий без блокировок глобального мьютекса.
- **Теория игр и алгоритм Minimax:** Разработка ИИ для поиска оптимального хода на дереве игровых состояний с рекурсивной оценкой выигрыша, ничьей и проигрыша.
- **Современная HTTP-маршрутизация Go 1.22+:** Применение встроенного сопоставления методов и шаблонов путей (`POST /game`, `POST /game/{id}`), извлечение параметров через `r.PathValue("id")`.
- **Многомодульные репозитории Go:** Организация проекта в виде независимых Go-модулей (`go.mod`) с локальным разрешением путей через директивы `replace`.

## Архитектура и стек технологий

Архитектура построена на четырех фундаментальных слоях:

1. **Domain (`tictactoe/domain`):**
   - Центральное ядро бизнес-логики.
   - Не содержит внешних зависимостей (исключительно стандартная библиотека `context`).
   - Определяет сущности `Game`, `Board`, правила игры и абстрактные контракты `GameRepository`, `GameService`.

2. **Datasource (`tictactoe/datasource`):**
   - Инфраструктурный слой доступа к данным и реализации вычислительной логики.
   - Реализует `GameRepository` с хранилищем `GameStorage` на базе потокобезопасного `sync.Map`.
   - Реализует `GameService`: валидация целостности ходов, проверка условий победы/ничьей, алгоритм минимакс.
   - Инкапсулирует внутренние структуры внутри пакета `internal` и предоставляет публичные конструкторы в `provide.go`.

3. **Web (`tictactoe/web`):**
   - Транспортный интерфейс REST API.
   - Инкапсулирует контроллер `GameHandler`, сериализацию/десериализацию JSON, CORS-заголовки и HTTP статус-коды.
   - Преобразует HTTP-запросы в доменные модели и отдает клиенту типизированные ответы `GameResponse`.
   - Экспортирует публичный фасад `Handler` в `provide.go`.

4. **DI (`tictactoe/di`):**
   - Модуль компоновки и точка входа (`main.go`).
   - Связывает воедино интерфейсы и реализации при помощи контейнера `go.uber.org/fx`.
   - Запускает HTTP-сервер и раздает клиентский веб-интерфейс `index.html`.

### Стек технологий

- **Язык программирования:** Go 1.26
- **DI-фреймворк:** `go.uber.org/fx` v1.24.0, `go.uber.org/dig` v1.19.0
- **Логирование:** `go.uber.org/zap` v1.26.0
- **Генерация идентификаторов:** `github.com/google/uuid` v1.6.0
- **Веб-сервер:** Стандартный пакет `net/http` с поддержкой Path Parameters (Go 1.22+)
- **Клиентский интерфейс:** HTML5, CSS3, Vanilla JavaScript (ES6+, Fetch API)

## Инструкция по сборке и запуску

### Требования к окружению

- Установленный Go версии 1.22 или выше (проект протестирован и оптимизирован для Go 1.26).
- Доступный сетевой порт `8000` / `8080`.

### Сборка и запуск сервиса

1. Перейдите в каталог точки входа приложения:
   ```bash
   cd src/di/cmd
   ```

2. Запустите веб-сервис:
   ```bash
   go run main.go
   ```

   При успешном старте Fx-контейнер инициализирует граф компонентов, выведет диагностические логи жизненного цикла и запустит HTTP-сервер.

### Доступ к приложению

1. Откройте веб-браузер и перейдите по адресу:
   ```text
   http://localhost:8000
   ```
   *(или `http://localhost:8080` в случае проксирования или запуска на соответствующем порту)*.

2. В интерфейсе игры отображается текущий хост подключения (по умолчанию `window.location.origin`). Для начала партии нажмите кнопку **«Новая игра»**. Сервер сгенерирует уникальный UUID сессии, после чего станет доступно игровое поле.
