Практический проект, посвященный реализации моделей конкурентного и многопоточного программирования на языке Go. В проекте на практике применены принципы взаимодействия последовательных процессов (Communicating Sequential Processes, CSP), организация параллельных пулов горутин с барьерной синхронизацией, потоковые конвейеры обработки данных на однонаправленных каналах, а также управление жизненным циклом фоновых сервисов и реализация паттерна Graceful Shutdown на базе контекста и перехвата системных сигналов ОС.

---

## О проекте

Проект входит в программу инженерной подготовки Go Bootcamp (Project 02) и направлен на освоение низкоуровневых и идиоматических механизмов конкурентности в среде выполнения Go (Go Runtime).

В отличие от традиционных моделей многопоточности с разделяемой памятью и блокировками мьютексов, реализация базируется на официальной парадигме Go: «Не общайтесь через разделяемую память; разделяйте память через общение». Репозиторий демонстрирует решение трех классических задач распределения и координации нагрузки:
1. Запуск изолированных параллельных воркеров с гарантированным ожиданием их завершения и агрегацией результатов без гонок данных (Data Races).
2. Построение асинхронного потокового конвейера (Data Pipeline) со строгой типизацией направлений каналов, контролем закрытия ресурсов и защитой от взаимных блокировок (Deadlocks).
3. Разработка долгоживущего фонового воркера с контролируемым циклом событий, отменой через `context.Context` и перехватом прерываний операционной системы (`SIGINT`, `SIGTERM`) для предотвращения утечек горутин (Goroutine Leaks) и корректного освобождения ресурсов.

## Ключевые навыки и освоенные концепции

- **Конкурентность и параллелизм (Goroutines):**
  - Диспетчеризация независимых легковесных потоков выполнения (`go func()`);
  - Использование возможностей Go 1.25 — метод `sync.WaitGroup.Go()`, инкапсулирующий вызов инкремента счетчика ожидания и отложенный декремент (`Done()`) при возврате из функции горутины;
  - Изоляция состояния горутин и безопасная запись результатов в срез по индексам воркеров.

- **Синхронизация и координация (`sync.WaitGroup`):**
  - Применение барьеров синхронизации (`wg.Wait()`) для гарантированного ожидания завершения пачки конкурентных задач перед переходом к постобработке данных;
  - Управление счетчиками завершения и координация горутин разной длительности выполнения.

- **Однонаправленные и двунаправленные каналы (`chan`, `<-chan`):**
  - Применение небуферизованных каналов для синхронной передачи данных между независимыми стадиями;
  - Использование однонаправленных каналов приема данных (`<-chan int`) в сигнатурах функций, что гарантирует защиту от непреднамеренной записи или несанкционированного закрытия канала потребителем;
  - Корректное закрытие каналов (`close()`) на стороне генератора данных (producer) и итерация потребителя через конструкцию `for ... := range channel`.

- **Паттерны Pipeline и Generator:**
  - **Generator Pattern:** инкапсуляция логики генерации числовой последовательности внутри горутины с возвратом канала только для чтения;
  - **Pipeline Pattern:** каскадное соединение независимых этапов обработки данных, где выходной канал предыдущего шага служит входным каналом для следующего, обеспечивая потоковую обработку без избыточного накопления промежуточных данных в оперативной памяти.

- **Управление жизненным циклом (`context.Context`):**
  - Использование механизма отмены `context.WithCancel` для трансляции сигнала завершения в дочерние горутины;
  - Обработка отмены контекста в цикле событий воркера через `select` и чтение из канала `<-ctx.Done()`;
  - Полное исключение утечек горутин при остановке родительского процесса.

- **Интервальная обработка и таймеры (`time.Duration`, `time.Sleep`):**
  - Моделирование случайных задержек обработки задач;
  - Организация дискретных интервалов тикера с отслеживанием прошедшего времени и номеров итераций.

- **Обработка системных прерываний и Graceful Shutdown:**
  - Подписка на сигналы операционной системы POSIX (`syscall.SIGINT`, `syscall.SIGTERM`) через буферизованный канал сигналов `os/signal.Notify`;
  - Реализация детерминированного завершения процесса: перехват сигнала прерывания -> вызов функции отмены контекста `cancel()` -> ожидание завершения последней итерации воркера через `wg.Wait()` -> вывод сервисного сообщения и завершение работы.

- **Интерфейс командной строки (`flag`):**
  - Строгая типизация и чтение целочисленных параметров командной строки (`flag.IntVar`);
  - Валидация аргументов, проверка количества переданных флагов (`flag.NFlag()`), граничных условий диапазонов и автоматический вывод документации (`flag.Usage()`).

## Архитектура и стек технологий

Проект разработан в рамках стандарта Go 1.25 и использует исключительно пакеты стандартной библиотеки Go (Zero External Dependencies), что гарантирует максимальную производительность, минимальный размер бинарных файлов и отсутствие уязвимостей стороннего кода.

- **Язык программирования:** Go (Go 1.25+);
- **sync:** координация выполнения параллельных горутин (`sync.WaitGroup`);
- **context:** трансляция сигналов завершения и контекстное управление вызовами (`context.Context`, `context.WithCancel`);
- **time:** работа с временными интервалами, задержками и длительностями (`time.Duration`, `time.Millisecond`, `time.Second`, `time.Sleep`);
- **os/signal & syscall:** низкоуровневое взаимодействие с ядром ОС, перехват прерываний `SIGINT` (Ctrl+C) и `SIGTERM` (завершение контейнера или процесса);
- **flag:** парсинг, валидация входных параметров запуска и отображение справочной информации CLI;
- **math/rand:** генерация псевдослучайных временных интервалов;
- **sort:** сортировка числовых результатов конкурентной обработки по убыванию (`sort.Slice`).

### Детальное описание реализации заданий

#### ex01: Параллельная обработка и барьерная синхронизация
- Принимает два обязательных CLI-флага: `-N` (количество параллельных горутин) и `-M` (максимальная задержка сна в миллисекундах).
- Создает срез фиксированного размера `make([]int, N)` для сохранения длительности сна каждой горутины.
- Запускает N горутин через конструкцию `wg.Go()`, где каждая горутина засыпает на случайное время `[0, M]` мс.
- Основной поток блокируется на `wg.Wait()` до полного завершения всех воркеров.
- После снятия барьера массив задержек сортируется по убыванию алгоритмом `sort.Slice` и выводится в консоль с указанием порядкового индекса.

#### ex02: Конвейерная обработка (Pipeline & Generator Pattern)
- Принимает флаги `-K` (начало диапазона) и `-N` (конец диапазона) с валидацией условия `N >= K`.
- Функция `generate(K, N) <-chan int` выступает генератором: создает небуферизованный канал, запускает горутину записи чисел от K до N и закрывает канал по завершении итерации.
- Функция `squere(in_ch <-chan int) <-chan int` является стадией преобразования конвейера: читает данные из входного канала, вычисляет квадрат каждого значения и передает в выходной канал, корректно закрывая его.
- Функция `main()` связывает звенья конвейера и последовательно вычитывает итоговые данные через `for val := range ch2`, предотвращая утечки памяти и дедлоки.

#### ex03: Управление жизненным циклом и Graceful Shutdown
- Принимает флаг `-K` — интервал шага тикера в секундах.
- Инициализирует корневой контекст с функцией отмены `context.WithCancel(context.Background())` и барьер `sync.WaitGroup`.
- Запускает фоновый воркер `ticker`, работающий в бесконечном цикле событий `select`. На каждой итерации проверяется сигнал завершения `case <-ctx.Done()`. При отсутствии сигнала воркер выполняет полезную работу (вывод тика и пройденного времени) и ожидает следующий интервал.
- Главный поток блокируется на чтении из канала системных сигналов `sigChan`, настроенного на `syscall.SIGINT` и `syscall.SIGTERM`.
- При получении сигнала (например, нажатии Ctrl+C) вызывается `cancel()`, воркер корректно выходит из цикла, вызывает `wg.Done()`, после чего `wg.Wait()` разблокирует завершение программы с финальным выводом статуса `Termination`.

## Инструкция по сборке и запуску

### Требования к окружению
- Установленный компилятор Go версии 1.25 или выше.

### Запуск через `go run`

#### 1. Задание ex01 (Параллельные воркеры и синхронизация)
Запуск 5 горутин с максимальным временем задержки 100 мс:
```bash
go run ./src/ex01/main.go -N 5 -M 100
```
Пример консольного вывода:
```text
0 	 91
1 	 62
2 	 50
3 	 28
4 	 26
```

#### 2. Задание ex02 (Конвейер чисел и обработка каналов)
Генерация и потоковое возведение в квадрат чисел от 1 до 20:
```bash
go run ./src/ex02/main.go -K 1 -N 20
```
Пример консольного вывода:
```text
1
4
9
16
25
...
400
```

#### 3. Задание ex03 (Graceful Shutdown и перехват сигналов)
Запуск периодического воркера с шагом тика в 2 секунды:
```bash
go run ./src/ex03/main.go -K 2
```
Пример работы и корректного завершения по нажатию `Ctrl+C` (`SIGINT`):
```text
Tick 1 since 2
Tick 2 since 4
Tick 3 since 6
^C
Termination
```
